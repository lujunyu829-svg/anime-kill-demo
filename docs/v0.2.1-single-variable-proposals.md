## 长残局候选（独立于角色数值）

两组当前代码压力 P99 为 43／41 轮；第 30–39 轮的 1V1 仍有合法出牌和持续防护。建议先以**只影响剩余两名存活角色且轮数达到 25**为条件，试验“每名角色每回合首次普通突击未被打出防御牌时，该次伤害至少有 1 点不能被护盾／防具抵消”。这保留防御牌的完整响应价值，不提前启动第 40 轮裂隙收束，也不改卡牌数量。它属于新增残局规则，必须先获得玩法批准；用固定种子复测两组压力各 10,000 局及弗兰奇／乔巴 1,000 局，目标 P99≤30、未完成／残留／超过80轮均 0，且常规第 25 轮之前对局的结果摘要完全一致。若仍不达标，回退并另提方案，不能仅把裂隙收束移到第 30 轮。

## 对照命令与证据格式

每一项试调在独立提交或隔离工作树上完成，记录 `git rev-parse HEAD` 与报告的 `sourceHash`。调整前后使用相同 `--seed=20260917`、角色池、anchor 和样本数，例如：

```powershell
npm test
npm run app:test
npm run balance:test -- --pool=one_piece_grand_line --characters=zoro --scenario=balance --games=250 --seed=20260917 --output=docs/reports/<候选名>-pure.json
npm run balance:test -- --pool=mixed --characters=zoro --scenario=balance --games=250 --seed=20260917 --output=docs/reports/<候选名>-mixed.json
```

这只是每角色 1000 局初筛。保留候选前必须在同一最终源码上重跑纯包每角色每 anchor 500 局、混合池每角色每 anchor 300 局、两组 10,000 局压力、军八 4,000 局、弗兰奇／乔巴 1,000 局，以及 `npm test`、`npm run build`、`npm run app:test`。每份记录写明角色自身胜率、四 anchor、梦想率、有效技能次数、平均／P99／最长轮数及连带越线角色；无法达到门槛时明确保留理由或回退。
