# v0.2.0 存档的版本化运行环境设计

## 目标与范围

v0.2.1 的桌面和 Android 离线包应让 v0.2.0 的 schema 2 未完成对局按当时的规则继续；没有旧存档时，新对局一律使用 v0.2.1。存档的命令日志、状态摘要及选择窗口不迁移或改写。此项只解决跨版本恢复，不调整角色数值、普通网页版入口或 v0.3.0 内容。

验收结果是：旧局能从多个未完成选择窗口确定性恢复并正常结束；完成或主动放弃后，用户返回 v0.2.1 大厅；损坏及未知版本存档不被覆盖，且可安全删除。

## 已确认的工程约束

- v0.2.0 与 v0.2.1 均使用 `anime-kill.saved-match.v2` 和 schema 2；存档含 `appVersion`。
- 存档以固定种子重放命令，`stateDigest` 用于校验。角色费用变化已使旧版娜美存档在新版引擎重放失败。
- 存下的 `engineState` 不含待处理回调和随机数完整运行状态，不能直接作为可运行引擎替换重放结果。
- `packaging/build.mjs` 构建 `www` 离线目录，Electron 与 Capacitor 共享此目录；普通网页版 `index.html` / `dist/app.bundle.js` 不参与包装存档机制。
- 当前与 v0.2.0 页面中的 DOM `id` 集合一致。实施时仍须验证旧运行脚本所用选择器、对话框和关键样式与当前 `www/index.html` 兼容。

## 运行环境选择

在封装版 `www/index.html` 中，以同源外部启动脚本取代直接加载 `dist/app.bundle.js`。启动脚本只读取本地存档的 `schemaVersion` 和 `appVersion`：

| 本地状态 | 加载脚本 | 大厅行为 |
| --- | --- | --- |
| 无存档、存储不可用、非 v0.2.0 存档 | v0.2.1 正常脚本 | 正常入口；当前存档检查负责显示损坏或不兼容提示 |
| schema 2 且 `appVersion` 为 `0.2.0` | 冻结的 v0.2.0 封装脚本 | 显示旧局继续入口及“旧版规则”提示 |

启动脚本不解释游戏命令，不执行存档迁移，不将存档内容插入 HTML，也不依赖网络。未知版本由当前 `inspectSavedMatch` 明确判为“不兼容”，而非尝试用当前引擎重放。脚本加载失败时显示可读错误和重试入口，不自动清理存档。

冻结脚本须由仓库中 v0.2.0 发布源码及其封装变换生成一次，放入 `packaging/legacy/v0.2.0/` 并记录 SHA-256。未来打包只复制该产物，不能在 CI 构建时依赖 Git 历史或重新用 v0.2.1 源码生成旧规则。旧脚本只用于继续已有 v0.2.0 对局；新脚本仍由现有构建流程生成。

## 旧局到新版的切换

旧局运行期间，`继续对局`、正常操作和恢复均留在 v0.2.0 运行环境。旧局终局会按旧会话逻辑清除存档；在结果弹窗选择“返回大厅”或“再来一局”时，启动桥接层刷新同一页面，于是加载 v0.2.1。旧版大厅中若选择新开对局或放弃存档，先由桥接层提示确认；确认后删除原存档并刷新，再由 v0.2.1 开新局。取消确认则保留旧局和当前页面。战斗中的“返回大厅”不删除存档，仍可继续旧局。

桥接层只拦截上述四种导航按钮，不介入牌、技能、AI 或结束回合的事件。旧版运行期间显示轻量、可读的版本提示，避免用户误以为旧局也已按新数值结算。切换到新版后，v0.2.1 的“继续对局”仅处理 v0.2.1 存档；旧版存档不会意外进入新版重放路径。

## 文件边界

- `packaging/runtime/boot.js`：读取版本、选择脚本、处理旧局退出/放弃的页面切换；不导入游戏引擎。
- `packaging/legacy/v0.2.0/app.bundle.js` 与校验记录：不可修改的旧版封装产物。
- `packaging/build.mjs`、`packaging/transform-app.mjs`：把启动脚本与旧产物放进 `www`，并保持 CSP 只允许同源脚本。
- `packaging/runtime/persistence.js`：当前运行环境明确拒绝未知或不匹配的 `appVersion`，并给出可删除的提示。
- 包装层测试：启动分流、按钮桥接、旧存档实际恢复与新局规则隔离。

不改变 schema 2、`SAVE_KEY` 或现有命令结构，不引入数据库、服务端和第三方迁移依赖。

## 测试与验收

1. 用冻结的 v0.2.0 运行环境和固定种子生成旧存档，分别停在响应、弃牌、角色多步选择及 AI 回合；在新封装入口恢复，比较恢复前后的状态摘要并继续至终局。特别覆盖旧版娜美零费用航海术存档。
2. 验证旧局返回大厅仍可继续；取消“放弃/新开”确认不改变存档；确认后刷新并使用 v0.2.1；终局“返回大厅/再来一局”也进入 v0.2.1。
3. 无存档、v0.2.1 存档、损坏 JSON、未知版本及本地存储不可用时，启动行为正确；损坏/未知存档不会静默删除或按错误规则重放。
4. 检查旧脚本所用页面元素和样式，并在 Windows 与 Android 离线包中各验证一次旧局恢复和新局启动。旧产物 SHA-256 必须与记录一致。
5. `npm test`、`npm run build`、`npm run app:test`、`npm run app:build` 均通过；保留现有 v0.2.1 平衡与专项验收未完成状态，不将此兼容项误记为整个版本发布通过。
